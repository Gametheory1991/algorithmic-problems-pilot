Date: 2026-11-01 (America/New_York)
Clearance rule for the whole pilot: public or synthetic data only. No FINRA TRACE,
no FINRA internal data, no terminal data, no employer systems. Every problem has a
machine-checkable verifier fixed BEFORE the run (pre-registered).

## The 10 problems

1. **Bin packing — greedy vs exact (run first; completed and verified 2026-11-01)**
   Question: How often does First-Fit Decreasing waste a bin on small instances, and what is the worst gap?
   Verifier: subset dynamic programming gives the provable optimum; both packings validated item-by-item.
   Data: synthetic, capacity 100, 12 items, uniform 15–60, 200 seeded instances.

2. **Sorting networks — can a comparator be removed? (completed and verified 2026-11-02)**
   Question: Take the known 8-input, 19-comparator network; is every comparator necessary?
   Verifier: zero-one principle — exhaustive check over all 256 binary inputs for the full network and for each single-comparator removal, with a concrete failing input as counterexample.

3. **Scheduling — Smith's rule, and where it breaks (completed and verified 2026-11-03)**
   Question: Smith's rule (order by ratio) is claimed optimal for minimising weighted completion time with no release dates. Verify exhaustively for all small instances, then find the smallest counterexample once release dates are added.
   Verifier: brute force over all permutations for n ≤ 8.

4. **Travelling salesman — heuristic gap on a public benchmark (completed and verified 2026-11-03)**
   Question: How close do nearest-neighbour + 2-opt get to the known optimum on the public TSPLIB eil51 instance (known optimum 426)?
   Verifier: published optimum; tour length recomputed independently, tour validity checked (every city once).

5. **Optimal stopping — prophet / secretary threshold (completed and verified 2026-11-03)**
   Question: What is the exact optimal threshold policy for the classic secretary problem at n = 10, 50, 100?
   Verifier: exact dynamic programming value vs 200,000-trial Monte Carlo simulation, fixed seed — the two must agree within simulation error.

6. **Multi-armed bandits — regret race on synthetic arms**
   Question: UCB1 vs Thompson Sampling vs epsilon-greedy: which has lowest cumulative regret on synthetic Bernoulli arms, including a non-stationary variant?
   Verifier: fully synthetic, seeded; regret computed against the known true best arm (known by construction).

7. **Optimal execution — closed form vs learned policy, synthetic market**
   Question: In a synthetic Almgren–Chriss market (simulated impact, no real market data), does a simple grid-searched policy beat the closed-form trajectory on expected cost + variance?
   Verifier: 100,000 seeded price paths, same paths for both policies (common random numbers).

8. **Coin systems — when is greedy optimal?**
   Question: For which coin systems up to value 200 is the greedy change-making algorithm optimal?
   Verifier: exact dynamic programming for the true minimum number of coins at every amount; smallest counterexample amount reported per failing system.

9. **Market making — quoting in a synthetic toxic-flow simulator**
   Question: In a Glosten–Milgrom-style synthetic simulator (informed / uninformed flow generated by code, no market data), what spread recovers zero expected loss to informed traders?
   Verifier: simulation with known informed share (known by construction); break-even spread solved analytically and checked against simulation.

10. **Exact counting for small SAT — testing a subexponential claim in miniature**
    Question: The Oct 26 OpenAI/math addition claims a deterministic subexponential exact counter for fixed-width CNF formulas. On small random 3-SAT instances, how does a DPLL exact counter's runtime actually scale vs brute force?
    Verifier: counts cross-checked by brute-force enumeration on every instance with ≤ 24 variables.

## Ranking logic
- Fastest verified result first: #1 (minutes, exact optimum), then #2 and #8 (exhaustive, minutes), then #3 (exhaustive, under an hour).
- Highest novelty per hour: #3's release-date counterexample and #10's scaling check.
- Closest to quant, still clearance-safe because fully synthetic: #7 and #9 — run later, they need more simulator code.

## Output standard (mirrors openai/math)
- Results grouped into families, released as raw manuscripts + code + result files, not polished claims.
- A result is only called proven when its verifier passed. Anything else is labelled conjecture / simulation evidence.
- Fixes and withdrawals logged in a history file, in public form if this is ever shared.
